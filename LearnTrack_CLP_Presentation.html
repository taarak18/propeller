⚠️ The Problem We're Solving

Why fragmented L&D data is a compliance and business risk

🔴 Fragmented Learning Data

  • Training attendance lives in the LMS
  • Assessment scores are in a separate system
  • Competency milestones are tracked in spreadsheets
  • No single view of an employee's learning health

🟡 Reactive — Not Proactive

  • At-risk employees identified only after compliance failure
  • No early-warning mechanism (4–6 weeks too late)
  • Interventions are ad hoc, not tracked systematically
  • No measurable outcome recording

🔵 Compliance Reporting Burden

  • Manual report assembly for GDPR, CCPA, DPDP, PIPEDA
  • No audit trail for automated profiling decisions
  • No consent management — legal exposure
  • Right-to-erasure requests handled manually
The cost: Organisations lose 4–6 weeks of remediation time, face regulatory fines, and cannot prove due diligence when an employee fails certification — all because their L&D data is siloed.

💡 Solution — What LearnTrack CLP Is

A lightweight aggregation, analytics and workflow SaaS layer on top of existing systems

Not a Full LMS — A Smart L&D Intelligence Layer

  • Consolidates attendance, scores & milestones from any existing LMS / HRIS
  • Builds a unified, curated learning profile per employee
  • Configurable rule engine detects at-risk learners automatically
  • Manages the full intervention lifecycle with SLA tracking
  • Produces compliance-ready reports with a full audit trail
  • Handles consent, opt-out and right-to-erasure across all regions

Key Architecture Decisions

  • Schema-per-service isolation (no cross-schema reads)
  • Transactional Outbox + CDC for exactly-once delivery
  • Multi-tenant via tenant_id on every DB row & Kafka event
  • Human-review gate on automated profiling (GDPR Art.22)
  • Temporal workflows for durable saga orchestration

POC Simplifications

  • Outbox + poller → Production: Debezium CDC
  • In-service state machine → Production: Temporal
  • Dev HS256 JWT → Production: Kong/JWKS/SSO
  • Single DB (schemas) → Production: DB-per-service

📥 Ingestion Service

  • Accepts training attendance, assessment scores, milestones
  • Idempotent — Idempotency-Key prevents duplicates
  • Publishes data.ingested via Outbox → Kafka

👤 Profile Service

  • Builds curated employee learning profile
  • Computes: Attendance %, Avg Score, Score Trend, Milestone %
  • Publishes profile.updated snapshot to Kafka

⚠️ Risk Engine

  • Evaluates configurable JSON rules against profile snapshot
  • Classifies: Critical / High / Medium / Low
  • Critical & High → human-review gate (GDPR Art.22)

📊 Reporting Service

  • CDC-fed read model (no polling — always fresh)
  • Consumes all domain events to build aggregates
  • Dashboard KPIs + compliance report generation

🔒 Human-Review Gate (GDPR Art.22)

  • All CRITICAL & HIGH assessments flagged requiresHumanReview = true
  • Employee is NOT notified until a Trainer/L&D Manager reviews
  • Reviewer must: Confirm, Override, or Dismiss
  • Decision + reviewer identity logged to immutable audit trail
  • 48-hour SLA — Temporal timer escalates to L&D Admin if breached

Consent Opt-Out Integration

  • Employee withdraws risk_profiling consent via Settings
  • consent.withdrawn event → Risk Engine skips assessments
  • Employee drops off the at-risk list immediately
  • Pseudonymised as REDACTED-… in compliance reports

⚙️ Rule Management

L&D Admins create rules via UI → test on sample profiles → activate. Redis cache invalidated instantly. Available metrics: attendance %, avg score, score trend, milestone completion %, days since progress.

Intervention Types

Remedial Training 1:1 Coaching Group Mentoring Self-paced Module

Who Does What

  • Trainer: Creates intervention, logs sessions, marks complete
  • L&D Manager: Approves or rejects, reviews escalations
  • Employee: Notified after review, sees schedule & notes

Outcome Measurement

  • Pre-intervention competency score recorded at creation
  • Post-intervention score recorded at completion
  • System calculates improvement % automatically
  • intervention.completed event → Risk Engine re-evaluates employee
  • Dashboard "Active Interventions" KPI updates live

SLA & Escalation

  • 48-hour approval SLA enforced via Temporal timer
  • SLA breach → intervention.escalated event
  • L&D Admin alerted immediately for Critical cases
  • Escalations visible in L&D Manager Escalation Queue

🗑️ Right-to-Erasure Saga (Temporal)

  • Employee submits erasure request via self-service portal
  • Temporal saga anonymises PII across all 6 services
  • Pseudonymises employee in all generated reports
  • Audit log entries retained (legally required) but de-linked
  • Signed deletion certificate generated and emailed
  • Target completion: 72 hours (regulated max: 30 days)

Immutable Audit Trail

Hash-chained audit log stored in S3 with Object Lock (WORM). Every consent decision, review action, and erasure event is tamper-proof. Full traceability for regulatory inspection.
