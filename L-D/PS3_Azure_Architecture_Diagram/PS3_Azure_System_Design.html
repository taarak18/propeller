📐 1. Architecture Overview

The platform is deployed as a cloud-native, multi-tenant SaaS application on Microsoft Azure using a microservices architecture. Each use case maps to one or more dedicated Azure services. Tenant isolation is enforced at every layer — network, compute, data, and identity — using Azure-native capabilities including Row-Level Security in Azure Database for PostgreSQL, Azure API Management per-tenant policies, and Azure Active Directory B2C for multi-tenant identity federation.

Architecture Principles

🏗️ Multi-Tenancy

  • Row-Level Security (RLS) in PostgreSQL
  • Per-tenant API keys via APIM
  • Tenant-scoped Azure AD B2C policies
  • Isolated Key Vault secrets per tenant

☁️ Cloud-Native

  • Azure Container Apps (microservices)
  • Azure Functions (serverless batch)
  • Azure Service Bus (async messaging)
  • Azure Front Door (global CDN + WAF)

🔒 Zero-Trust Security

  • Azure AD B2C + SAML/OIDC federation
  • Azure Key Vault for all secrets
  • Private Endpoints for all data services
  • Azure DDoS + WAF protection

📊 Observability

  • Azure Application Insights
  • Azure Log Analytics Workspace
  • Azure Monitor + Alerts
  • Azure Dashboard per tenant

🔧 3. Microservices Architecture — Azure Container Apps

All backend services run as Azure Container Apps within a shared environment using Dapr for service-to-service communication, state management, and pub/sub messaging. Each service is independently scalable, deployable, and monitored.

tenant-api

  • UC-01: Self-service onboarding
  • UC-02: Super Admin tenant mgmt
  • UC-03: Subscription tier enforcement

  • Azure: Container Apps + PostgreSQL

identity-api

  • UC-04: SSO configuration (SAML/OIDC)
  • JWT token issuance with tenant_id claim

  • MFA policy enforcement for admins

🗄️ 4. Data Architecture — Azure Data Services

4.1 Azure Database for PostgreSQL Flexible Server (Primary Store)

Configuration

  • SKU: General Purpose, 8 vCores, 32 GB RAM
  • Storage: 1 TB with auto-grow enabled
  • High Availability: Zone-redundant standby
  • Read Replicas: 1 replica in same region
  • Backup: 35-day retention, geo-redundant
  • Private Endpoint: No public internet access
  • Encryption: Azure Key Vault CMK

Row-Level Security (RLS) Design

  • All tables include tenant_id UUID NOT NULL
  • RLS Policy: USING (tenant_id = current_setting('app.tenant_id')::uuid)
  • Application sets SET app.tenant_id = '{tenant_id}' per request
  • No query can return cross-tenant data at DB level
  • Separate read-only role per tenant for reporting

-- UC-01 UC-02 UC-03 · Tenant master record
CREATE TABLE tenants (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  domain            VARCHAR(255) UNIQUE NOT NULL,
  name              VARCHAR(255) NOT NULL,
  tier              VARCHAR(50)  NOT NULL DEFAULT 'BASIC',  -- BASIC|PROFESSIONAL|ENTERPRISE
  status            VARCHAR(50)  NOT NULL DEFAULT 'PENDING_SETUP',
                                           -- PENDING_SETUP|ACTIVE|SUSPENDED|CANCELLED
  admin_email       VARCHAR(255) NOT NULL,
  activated_at      TIMESTAMPTZ,
  suspended_at      TIMESTAMPTZ,
  metadata          JSONB        DEFAULT '{}',
  created_at        TIMESTAMPTZ  DEFAULT NOW()
);
CREATE INDEX idx_tenants_domain ON tenants(domain);
CREATE INDEX idx_tenants_status ON tenants(status);

-- UC-03 · Subscription plan definitions (global catalogue)
CREATE TABLE subscription_plans (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  name              VARCHAR(50) UNIQUE NOT NULL,   -- BASIC|PROFESSIONAL|ENTERPRISE
  max_employees     INT,                            -- NULL = unlimited
  max_risk_rules    INT,                            -- NULL = unlimited
  max_api_calls_min INT,                            -- per-minute rate limit
  features          JSONB   NOT NULL,               -- feature flag map
  monthly_price_usd DECIMAL(10,2),
  created_at        TIMESTAMPTZ DEFAULT NOW()
);

-- UC-03 · Active and historical subscriptions per tenant
CREATE TABLE tenant_subscriptions (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id         UUID    NOT NULL REFERENCES tenants(id),
  plan_name         VARCHAR(50) NOT NULL,
  status            VARCHAR(50) DEFAULT 'ACTIVE',  -- ACTIVE|CANCELLED|PAST_DUE
  billing_cycle     VARCHAR(20) DEFAULT 'ANNUAL',  -- MONTHLY|ANNUAL
  started_at        TIMESTAMPTZ DEFAULT NOW(),
  expires_at        TIMESTAMPTZ,
  cancelled_at      TIMESTAMPTZ,
  stripe_sub_id     VARCHAR(255),
  created_at        TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_subscriptions_tenant ON tenant_subscriptions(tenant_id, status);

-- UC-03 · Daily usage metering per tenant (employees, API calls, storage)
CREATE TABLE usage_metering (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id         UUID    NOT NULL REFERENCES tenants(id),
  metric_date       DATE    NOT NULL,
  active_employees  INT     DEFAULT 0,
  api_calls_count   BIGINT  DEFAULT 0,
  storage_bytes     BIGINT  DEFAULT 0,
  report_count      INT     DEFAULT 0,
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(tenant_id, metric_date)
);

-- UC-01 UC-05 · Per-tenant API keys for external system ingestion
CREATE TABLE tenant_api_keys (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id         UUID    NOT NULL REFERENCES tenants(id),
  key_hash          VARCHAR(255) NOT NULL,  -- SHA-256 of actual key
  key_prefix        VARCHAR(10)  NOT NULL,  -- first 8 chars shown in UI
  name              VARCHAR(255),
  is_active         BOOLEAN DEFAULT TRUE,
  last_used_at      TIMESTAMPTZ,
  expires_at        TIMESTAMPTZ,
  created_by        UUID,
  created_at        TIMESTAMPTZ DEFAULT NOW()
);
CREATE UNIQUE INDEX idx_api_keys_hash   ON tenant_api_keys(key_hash);
CREATE INDEX        idx_api_keys_tenant ON tenant_api_keys(tenant_id, is_active);

-- UC-04 · Per-tenant SSO configuration (SAML 2.0 / OIDC)
CREATE TABLE tenant_sso_configs (
  id                UUID    PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id         UUID    NOT NULL REFERENCES tenants(id) UNIQUE,
  protocol          VARCHAR(20) NOT NULL,           -- SAML2|OIDC
  -- SAML fields
  idp_metadata_url  VARCHAR(500),
  idp_entity_id     VARCHAR(500),
  idp_sso_url       VARCHAR(500),
  idp_certificate   TEXT,
  -- OIDC fields
  oidc_client_id    VARCHAR(255),
  oidc_issuer_url   VARCHAR(500),
  oidc_scopes       VARCHAR(500),
  is_active         BOOLEAN  DEFAULT FALSE,
  tested_at         TIMESTAMPTZ,
  created_at        TIMESTAMPTZ DEFAULT NOW(),
  updated_at        TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE users (

  full_name         VARCHAR(255),

  b2c_object_id     VARCHAR(255),                   -- Azure AD B2C object ID

  created_at        TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(tenant_id, email)
);
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON users
  USING (tenant_id = current_setting('app.tenant_id')::uuid

CREATE INDEX idx_users_tenant ON users(tenant_id);
CREATE INDEX idx_users_b2c    ON users(b2c_object_id);

ALTER TABLE user_roles ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON user_roles

-- UC-05 · Assessment score records ingested from assessment system
CREATE TABLE assessment_scores (

  USING (tenant_id = current_setting('app.tenant_id')::uuid);
CREATE INDEX idx_assessments_emp  ON assessment_scores(tenant_id, employee_id);
CREATE INDEX idx_assessments_date ON assessment_scores(tenant_id, taken_at DESC);

6.2 Key APIM Policies

<!-- Per-Tenant Rate Limiting Policy -->
<policies>
  <inbound>
    <!-- Validate JWT from Azure AD B2C -->
    <validate-jwt header-name="Authorization" require-expiration-time="true">
      <openid-config url="https://{b2c-tenant}.b2clogin.com/{tenant}/v2.0/.well-known/openid-configuration"/>
      <required-claims>
        <claim name="tenant_id" />
        <claim name="roles" />
      </required-claims>
    </validate-jwt>

    <!-- Extract tenant_id from JWT and set as context variable -->
    <set-variable name="tenantId" value="@(context.Request.Headers["X-Tenant-Id"].First())" />

    <!-- Per-Tenant Rate Limiting (keyed by tenant_id from JWT) -->
    <rate-limit-by-key calls="1000" renewal-period="60"
      counter-key="@(context.Request.Headers.GetValueOrDefault("X-Tenant-Id",""))"
      increment-condition="@(context.Response.StatusCode < 500)" />

    <!-- Inject tenant_id into backend header for RLS -->
    <set-header name="X-Tenant-Id" exists-action="override">
      <value>@((string)context.Variables["tenantId"])</value>
    </set-header>

    <!-- Route to correct backend Container App -->
    <set-backend-service backend-id="tenant-specific-backend" />
  </inbound>
  <backend><forward-request /></backend>
  <outbound>
    <!-- Add correlation headers -->
    <set-header name="X-Request-Id" exists-action="override">
      <value>@(context.RequestId.ToString())</value>
    </set-header>
  </outbound>
</policies>

⚙️ 7. Batch Processing & Event-Driven Architecture

7.1 UC-08 — Nightly Risk Evaluation (Azure Functions + Container Apps Jobs)
